## Context

菜单树是后端 / mock 下发的单一真相源（`authStore.menus`），侧边栏直接渲染。ant-design-vue 4.2.6 折叠态隐藏文字的样式 `.ant-menu-item-icon + span { opacity: 0 }` 只在 icon 元素存在时生效，且 `MenuItem` 仅对「有 icon 的项」附加 `.ant-menu-item-icon` 类——这是本变更的硬约束。接口层（MSW / 真实后端）只能传可序列化字符串，不能传组件实例。

## Goals / Non-Goals

**Goals:**

- 图标名随菜单树下发，前端白名单解析，折叠态正确收敛为纯图标
- 根级菜单永不缺图标（兜底），子级菜单按需渲染
- 脚手架生成 / 重建菜单不破坏图标配置

**Non-Goals:**

- 不做图标按需自动注册 / 动态 import 任意图标名（白名单收敛足够）
- 不改路由权限契约（code / meta.code 机制不变）
- 不引入第三方图标库（沿用 `@ant-design/icons-vue`）

## Decisions

1. **字符串 + 白名单注册表，而非配置里直接存组件**
   菜单树来自接口，必须可序列化；白名单同时收敛运行时可渲染面，未注册名字不进动态解析。备选「前端按 routeName 映射图标」被否：绕开菜单单一真相源，后端无法控制图标。

2. **根级兜底、子级严格的两个解析函数**
   折叠态只有根级菜单项会失去文字，缺图标即视觉破损，故 `resolveRootMenuIcon` 必须兜底；子级在弹层中始终显示文字，缺图标无副作用，`resolveMenuIcon` 严格返回 undefined 避免无意义默认图标泛滥。备选「单一函数全局兜底」被否：子项会出现成排无意义的通用图标。

3. **icon 必须渲染在 `#icon` 插槽内**
   antd 只给插槽内容附加 `.ant-menu-item-icon` 类，渲染在默认插槽不会触发折叠隐藏样式。已在布局模板中以注释固化该约束。

4. **脚手架重建透传 icon**
   `rebuildDomainMenu` 整体替换菜单对象，若不提取原 `icon` 再写回，用户自定义图标会在下次 `scaffold:feature` 时静默丢失（与 label 沿用同一模式）。缺失时补 `AppstoreOutlined` 保持「根级必有图标」不变式。

5. **折叠标题收缩为首字符**
   折叠宽度 80px 放不下完整应用名；不做宽度动画（文本内容切换无法过渡），保持与 antd 侧栏宽度过渡并行的简单交换。

## Risks / Trade-offs

- [新菜单项忘记配 icon] → 根级运行时兜底 + 脚手架默认写入 + 契约测试防拼写错误；子级缺 icon 无视觉影响
- [白名单图标不足] → 注册表为普通常量表，按需追加一行即可；契约测试在配置侧兜住「声明未注册」
- [标题首字符对多语言应用名语义不清] → 当前为中文单品牌名场景，可接受；未来可配置化

## Migration Plan

纯增量变更，无数据迁移；回滚即 revert 提交。菜单数据向后兼容（`icon` 可选，旧数据不报错）。
